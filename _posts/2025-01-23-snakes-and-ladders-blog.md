## How the Game Works

Our Snakes and Ladders game is a gamified educational platform built to teach AP Computer Science Principles concepts through an interactive board game experience. The game follows a structured progression: users first log in through the website's JWT-based authentication system (or play as a guest in demo mode), then select one of four pixel-art characters (Knight, Wizard, Archer, or Warrior) before entering the game board. The board is divided into three major sections. Section 1 (Squares 1-6) consists of five interactive lessons covering programming basics, data structures, networking, cybersecurity, and data ethics, each awarding bullets upon completion. Section 2 (Squares 7-56) is the question gauntlet, where players roll a dice to advance across 50 squares, each containing a multiple-choice question from one of five CS topics. Correct answers earn bullets that serve as ammunition for the final section. Upon reaching Square 56, players unlock the Boss Battle, a real-time multiplayer arena where up to 7 players cooperate via WebSocket connections to defeat a dragon boss using their accumulated bullets. The boss features complex AI with multiple movement patterns (dash, zigzag, chase, circle), and players can collect powerups (damage boost, speed boost, rapid fire, and health restore) that spawn every 5 seconds on the arena. A group chat runs alongside the battle for real-time coordination, showing notifications for player joins, powerup pickups, and defeats. The game's purpose is to make learning CS Principles engaging by tying knowledge directly to gameplay progression, where understanding the material literally gives you the firepower to win.

## Technical Architecture & Transactional Data

The frontend is built as a set of static HTML/JS/CSS pages served through Jekyll, while the backend runs on Flask (Python) with a SQLite database in development and MySQL in production. The core frontend files include `game-board-part1.html` (lessons and character selection), `game-board-part2.html` (question board), and `boss-battle.html` (multiplayer arena), supported by `snakes-game.js` for shared game logic, `questions_bank.js` for the 50-question pool, and styling via `snakes-game.css`. On the backend, `api/snakes_game.py` and `api/snakes_extended.py` expose RESTful endpoints, `api/boss_battle.py` handles battle room management, and `socket/boss_battle.py` manages real-time WebSocket events. The data models (`model/snakes_game.py` and `model/boss_room.py`) define the database schema. Transactional data flows constantly between frontend and backend: when a user completes a lesson, `POST /api/snakes/complete-lesson` sends `{lesson_number, bullets_earned}` and the server appends the lesson to the `completed_lessons` JSON array and increments `total_bullets`. When answering questions, `POST /api/snakes/answer-question` sends `{square, bullets_earned, correct}` and the server updates `current_square`, `visited_squares`, and conditionally awards bullets. The game autosaves every 10 seconds via `PUT /api/snakes/` with the full game state (`current_square`, `visited_squares`, `total_bullets`, `lives`, `time_played`, `completed_lessons`, `unlocked_sections`). The boss battle uses both REST and WebSocket transactions: `POST /api/boss/join` creates or joins a room and returns a `room_id`, then Socket.IO events (`boss_player_move`, `boss_damage`, `boss_player_hit`, `boss_powerup_collected`, `boss_chat_send`) handle real-time state synchronization across all players at 50ms intervals for position and 5-second intervals for powerup spawning. The leaderboard is fetched via `GET /api/snakes/leaderboard`, returning the top 10 players sorted by `total_bullets`. Authentication flows through JWT tokens stored in HttpOnly cookies, verified on every API call via the `@token_required()` decorator, with the user ID extracted from the token payload to associate game data with the correct `SnakesGameData` database record.

## Team Work Split

The development of the Snakes and Ladders game was split across six team members, each owning distinct areas of the project. **Akhil** (Scrum Master) led project coordination, managed sprint planning and stand-ups, built the main game board UI and dice-rolling mechanics across `game-board-part1.html` and `game-board-part2.html`, implemented the character selection carousel, and integrated the frontend navigation flow between all game pages. **Moiz** (Assistant Scrum Master / DevOps) handled all backend deployment infrastructure including the Dockerfile, docker-compose configuration, Nginx reverse proxy setup (`nginx_file`), production environment variables, the Flask application factory, and CORS configuration; he also built the authentication system (`api/authenticate.py`) with JWT token issuance, cookie management, and the `@token_required()` decorator that secures all game API endpoints. **Samarth** developed the lesson system, creating the five interactive lesson pages (`lessons/lesson1-5.html`) with their arcade-style CSS, the `POST /api/snakes/complete-lesson` endpoint, section unlocking logic, and the lesson completion tracking that gates progression to Section 2. **Arnav** built the question system end-to-end, including the `questions_bank.js` file with 50 questions across 5 CS topics, the question modal template (`question_template.html`), the `POST /api/snakes/answer-question` endpoint with bullet-awarding logic, and the square visit tracking that prevents re-answering. **Ethan** developed the boss battle arena, implementing the full `boss-battle.html` with canvas-based rendering, pixel-art character sprites, boss AI movement patterns, bullet physics, powerup spawning/collection mechanics, the `api/boss_battle.py` REST endpoints for room management, and the `model/boss_room.py` database models (`BossRoom`, `BossPlayer`, `BossBattleStats`). **Aneesh** built all real-time multiplayer and social features, including the complete `socket/boss_battle.py` WebSocket handler with player synchronization, the group chat system (lobby and in-battle messaging), the leaderboard API and frontend display, the active players tracking system, the autosave mechanism, and the demo/guest mode that uses sessionStorage for progress without requiring authentication.
