A comprehensive gamified learning platform with authentication, persistent storage, and multiplayer features

⏰ Final Sprint Due: December 12, 2025

📋 Big Ideas & Purpose

The Snakes & Ladders quest gamifies the learning experience on your existing website. Players log in with the same credentials used by other site modules and start in Section 1, which has the Start square and five lessons (learning tasks). Completing these lessons unlocks Section 2, a 5×10 board representing ~50 question squares. As players answer questions correctly they move toward the end; the top ten players on the leaderboard can unlock a boss battle room.

📊 What the Game Tracks

Persistent State (Stored in Database)

  • Bullets (Points): Player scoring system
  • Lives: Player health tracking
  • Current Square: Player position on board
  • Completed Lessons: Progress through Section 1
  • Visited Squares: JSON list of squares visited
  • Unlocked Sections: Access to new game areas

All of this state is persistent – it is stored in a database via Flask back‑end models and returned through REST API calls (GET/POST/PUT/DELETE) to the front‑end.

🎯 Control Structures in Action

Selection (If/Else)

Decides which modal to display, applies snake/ladder logic, checks prerequisites for boss battle

Iteration (Loops)

Builds 5×10 game board, attaches event listeners, traverses visited squares list

Sequencing (Order)

Authentication → Data retrieval → State update → Render → Database save

📂 How the Code Connects Everything

🎨 Front-End (JavaScript/HTML)

The snakes-game.js script loads when the user navigates to the game pages. It defines the game state with fields such as bullets, lives, currentSquare and visitedSquares and hooks up event listeners for login buttons, character selection cards and dice rolls.

Selection and iteration are used extensively: A loop attaches click listeners to each .character-card to allow players to pick a character, and conditional statements decide whether the player can roll the dice or needs to complete a lesson.

The createGameBoard function iteratively builds the grid of squares and uses selection to label squares as snakes, ladders or boss squares.

The movePlayer function updates the current square, ensures the player bounces back if they overshoot the end, calls createGameBoard and handleSquareEvent in sequence, and uses control flow (selection) to apply snakes or ladders.

↓

🔌 API Layer (Flask)

The back‑end provides REST endpoints for creating, reading, updating and deleting the game record.

  • api/snakes_game.py exposes endpoints like /api/snakes/ (POST – create game record; GET – get current player record), /api/snakes/leaderboard (GET), and add-bullets or update-square for partial updates.
  • api/snakes_extended.py handles higher‑level operations such as marking lessons complete, awarding bullets for questions and unlocking subsequent sections.
  • api/boss_battle.py coordinates the boss battle, which allows players to join a boss room, attack the boss, take damage and leave.

All of these endpoints use sequencing: they perform authentication, validate request data, update the database, and then return updated JSON.

↓

💾 Database & Models

model/snakes_game.py defines the SnakesGameData SQLAlchemy model. Each record stores:

  • userId
  • username
  • total bullets
  • time played
  • current square
  • lives
  • visited squares (JSON list)
  • completed lessons
  • unlocked sections
  • other fields

This persistent storage ensures that progress survives page reloads and supports analytics (leaderboards, quest predictions). The mutable_list type allows the model to track changes to the visited squares list without manual serialization.

🔐 Flask Login & Personalized Data

The game uses the existing login system; the front‑end calls jwt_authorize endpoints to obtain a token and stores it in localStorage. The back‑end uses this token to identify users and returns personalized Snakes & Ladders data (bullets, current square, lives, etc.). Authenticated sessions allow each player to track progress independently, fulfilling the user interaction and authentication requirements.

Key Insight: The selection, iteration and sequencing control structures are fundamental to this project. Selection is used in movePlayer and handleSquareEvent to decide whether to show a lesson, question or boss battle. Iteration constructs the board and attaches event listeners; loops also traverse the visitedSquares list to determine unvisited question squares. Sequencing ensures that operations occur in order—authentication before data retrieval, updating the game state before rendering, and saving progress to the database after each move.
